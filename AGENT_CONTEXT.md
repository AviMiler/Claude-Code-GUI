## What This Project Is
A local web GUI for the Claude Code CLI that looks and works like the Claude desktop app (Code tab), in Hebrew/RTL.
A zero-dependency Node.js server keeps one long-lived `claude -p --input-format stream-json --output-format stream-json`
process per session and talks to it with the CLI's control protocol. Everything the terminal offers under `/`
is reachable: every slash command, skills, agents, MCP servers, plugins, hooks, memory, permissions, context, resume.
Built for a corporate Windows machine without another terminal; the target model is LOCAL (qwen through Ollama at `ANTHROPIC_BASE_URL`), Claude Code 2.1.246.

## Entry Points
- `server.js` — starts the HTTP server (loopback only)
- `public/js/app.js` — frontend entry (ES modules, no build step)
- Run: `node server.js`, open http://127.0.0.1:3737. Set `claudePath` (and `model` / `env` / the 2026-11-16 keys `contextWindow`, `contextWarnPercent`, `stallSeconds`, `modelGate`, `verifyMaxAttempts`, `loopRepeat`) in `config.json`.
- Tests: `node --test test/*.test.js` (Node's built-in runner; the bare-folder form fails on Node 22). They use temporary `CLAUDE_GUI_DATA` / `CLAUDE_CONFIG_DIR`.
- After pulling an update: restart `node server.js`. Files in `public/` are read from disk on every load, but API routes load only at startup, so a new screen against an old server fails (the 404 says so).
- Develop without an API key: `CLAUDE_GUI_CONFIG=dev/config.fake.json CLAUDE_GUI_DATA=<temp dir> node server.js` (port 3738). `dev/fake-claude.cmd` runs on Windows only; elsewhere point `claudePath` at a shell script that runs `node dev/fake-claude.js "$@"`. `"FAKE_CLAUDE_STARTUP_MS": "2500"` under `env` feels the real startup delay. For the model list point `ANTHROPIC_BASE_URL` at a small server answering `GET /v1/models` with `{ data: [{ id }] }` (`dev/fake-ollama.js` also answers `/api/show` and `/api/ps`).

## Key Patterns Used
- All knowledge of the CLI event format is in `lib/event-translator.js`; control-protocol calls in `lib/cli-process.js`.
- Every UI update flows through one path: server broadcast -> SSE (`event-hub.js`) -> `public/js/events.js` -> views.
- Slash commands: `public/js/commands-data.js` merged with the live catalog (`command-catalog.js`); executed by `command-runner.js`.
- Optional CLI flags are passed only when `claude --help` lists them (`lib/cli-capabilities.js`).
- The browser reaches Claude's own files only through kinds (`lib/claude-files.js`) and whitelisted CLI subcommands (`lib/cli-commands.js`); writes need an explicit folder.
- The UI never waits for the CLI to open a menu (`peekCatalog`, `peekModels`); background reads pass `ifRunning` so they never start a process.
- Claude's state is a `data-state` on the working line and the crab inside it (`setCrabState`); motion lives only in `public/css/animations.css`.
- Significant actions are only confirmed, never blocked (`guardedApi`, `confirmRisk` in `public/js/risk.js`).
- A feature gets its own folder (`lib/<feature>/`, `public/js/<feature>/`); the context percentage has ONE function (`public/js/context/context-info.js`).

## Gotchas / Watch Out
- The CLI is the source of truth, the GUI only displays (DECISIONS.md 2026-10-29): if the CLI already does it, follow the CLI; keep GUI data only for what the CLI has no place for; a departure (a second copy of history, an invented flag or control request) is said out loud in the reply and in DECISIONS.md. Already flagged GUI-only: model gate, stall clock, loop detector, "סכם ונקה", the context-window lookup.
- Size budget (~150 lines per file): `session-service.js` 174, `session-runtime.js` 154, `app.js` 153 (one long line), `thread.js` 144, `fake-claude.js` 150, `files-pane.js` 134: add nothing there beyond in-place edits and one hook line; put new logic in a new module. Several hand-merged files have two statements on one line.
- Session options (D16, F): a new per-session CLI option is an entry in `lib/session-options.js` (`textChanges`, `optionArgs`, `copiedOptions`) plus a field in `session-store.js` `create`, `SETTING_KEYS` in `session-service.js` and a restart key in `session-runtime.js` `applySettings`. Free text never goes through argv (`quoteForCmd` refuses `%`): use a file (`session-prompt.js`); tool names are plain names. Every place that sets a permission mode passes the session's `safeMode` to `requireMode` (`updateSession`, `answerPermission`, checked BEFORE the CLI is told); a CLI-reported mode change is not blocked. `COLOR_KEYS` (server) and `public/js/session-color/palette.js` change together. A new `startProcess` caller needs `withSessionEnv` and `withCheckpointing`. A new place that deletes a session calls `removePromptFile` (and must release the model gate, kill a verify run and forget the stall / loop state).
- `--settings`: the per-session file holds the output style AND the verify Stop hook (`verify-hook-settings.js` merges them); pass it only when `--help` lists it. The verify secret travels in the CLI's environment, not the file. The hook is always installed; the server answers allow with no stored check. The hook command is run by the CLI's shell: refuse paths with `" % $` backtick `!`, newline, `\\`. A blocked Stop continues the SAME turn: verify notices are notice items, never user items (do not split `isTurnStart`); `session.verifying` pauses the stall clock.
- Model gate / stall: the slot is held to the real turn end (a held correction turn stays held); every exit path must release it (idle status, delete, archive of a holder = stale, 30 s stale check); a waiting turn is `modelWait` on a running session, not `session.queue` (the queue's strip and Stop semantics differ). `/btw`, corrections and warm-up bypass the gate. The stall text updates the working line in place (moving that node restarts the crab animation).
- Loop detector: only top-level tools; the loop stop is not a user stop (no "הריצה הופסקה.", it notifies as an error) and leaves queued texts parked; keep BashOutput / TaskOutput / Monitor / KillShell exempt.
- Context window: the denominator and the estimate are derived data: label them ("הערכה"), never start a CLI for the ring (`ifRunning`), never ping the cloud (custom base URL only), keep `contextInfo(session)` the ONLY place that computes a percentage, reset the estimate at `/clear` (`cleared: true` divider) and `/compact`. Do not invent an env var to make the CLI auto-compact early.
- Robustness: `session-store.js` goes through `lib/safe-file.js` (the exit write stays synchronous; a file that failed to load is never overwritten); requiring `session-store.js` registers an exit hook that writes `data/sessions.json`, so set `CLAUDE_GUI_DATA` in experiments. The SSE hub's `resync` must reload state in `api.js` `subscribe`; a new event type needs an id (the hub assigns it).
- Rewind (D15): `session.resumeAt` is NOT cleared until the replay of the next message arrives (`onUserReplay`); a message is a rewind point only when `cliSession === claudeSessionId` and `!forkPending` (so anything that changes `claudeSessionId` on purpose changes what is rewindable; this is also why "fork then rewind in the fork" cannot work for compare). `afterUuid`: `null` = first message, `false` = unknown. Validate the cut BEFORE restoring files (`requireCutPoint`); never take a path, folder or program from the rewind request; `rewind_files` stays out of `catalog-service.js`. Any new place that sends a user message to the CLI goes through `startTurn` / the correction path (so the item gets `cliUuid` and `afterUuid`) and calls `shell-context.withPending` / `restore`. Retry reuses the rewind route.
- Revert one hunk: the request never carries patch text; every git call goes through `lib/git/run.js` (`SAFE_GIT`, `SAFE_DIFF`, `core.quotepath=false`; `git()` takes `input` and `{ timeoutMs }`); never call `execFile('git')` elsewhere. The only git writes: the session worktree (`lib/git/worktree*.js`, repository hooks and filters run on purpose), the hunk revert and, since 2026-11-16, commit and push (`lib/git/commit*.js`, `push.js`: never an option from the request, never `--no-verify` / `--amend` / `--force`). The hunk hash module is shared by browser and server (loaded as a data: URL ES module): keep it pure.
- Files pane (D11): the file routes take the session from the server and only a path from the request; write rules live in `lib/files/safe-path.js` (no `.git` segment, no `DATA_DIR` / `CONFIG_PATH`, no uploads, no `:` on win32, regular files only): every route that writes a file uses it. `overwrite` forces only when exactly `true`. A new way to show an editable path goes through `files/open-in-files.js`; the split pane has no edit entry. A save calls `invalidateSessionFetches`. The editor handles Ctrl+S and Esc itself.
- Shell (D10): the folder is always `session.cwd` and the shell is an enum; never take a folder, program or environment from the request. Every kill path matters (stop, delete, archive, server exit, SIGINT / SIGTERM / SIGHUP): a new way to end a session calls `shell-runs`. `session.shellContext` is set only by the server when a `bang` run ends and must reach the CLI exactly once. The `!` live card bypasses `thread.js` on purpose (still appended below the working line). The Terminal pane's runs are browser memory only.
- Context menus (D7): a new place that shows a file path adds `data-file-path` (the FULL path; the Changes pane uses `joinPath(root, path)`); a new place that lists sessions adds `data-session-id` and calls `enableSessionMenus`. Row actions take an id and never select the row. Use `openContextMenu` (keyboard navigation), not `showDropdown`, for a menu that can open from the keyboard; Shift+F10 is fired by the browser as `contextmenu`.
- Archived sessions (D6): `archived` / `archivedAt` are set only by `lib/session-archive.js`. Archive marks the session FIRST and stops the turn AFTER (so the stopped turn's `dispatchNext` skips it); do not swap that and do not call `stopSession` from archive. Archived sessions stay in `state.sessions`, so every NEW list or counter decides about `!session.archived` (sidebar, split picker, `page-status.js`, unread mark, `notify.js`, `warm-up.js`). A session whose worktree was removed has no folder: any route that starts a CLI or runs in `session.cwd` goes through `requireRunnable` (409); git views answer `folderMissing`. Restore puts the folder back at the SAME path; `archiveSession` skips removal while a non-archived session uses the path (`worktreeInUse`), `deleteSession` counts every other session; the two checks differ. Like `stopSession`, `archiveSession` removes its `stopRequested` mark again when `interrupt` finds no active turn.
- Worktree sessions (D5): `session.cwd` is the worktree but the user's PROJECT is `worktree.source`: anything that shows or groups by folder uses `projectFolder(session)` (`public/js/worktree/project-folder.js`; the verify check is stored per project folder); anything that runs git, reads files or starts the CLI uses `session.cwd`. `worktree` is set only by the server (never from a request body, never by PATCH).
