## What This Project Is
A local web GUI for the Claude Code CLI that looks and works like the Claude desktop app (Code tab), in Hebrew/RTL.
A zero-dependency Node.js server keeps one long-lived `claude -p --input-format stream-json --output-format stream-json`
process per session and talks to it with the CLI's control protocol. Everything the terminal offers under `/`
is reachable: every slash command, skills, agents, MCP servers, plugins, hooks, memory, permissions, context, resume.
Built for a corporate Windows machine without another terminal.

- ⚠️ Known security issues, accepted on purpose (closed network, single user; details in ARCHITECTURE.md → Security):
  1. Cross-site GET: a website open in the same browser can trigger GET endpoints (no Origin is sent for simple GETs).
     Responses are unreadable, but `/api/catalog?cwd=` starts a `claude` probe in any folder (in `-p` mode the folder's
     own settings/hooks load without a trust prompt), `/api/git` runs git there, `/api/folders` lists folders,
     `/api/models` and `/api/model-health` make the server call the model server, and repeated calls can exhaust memory.
  2. No authentication: any program or user on the machine can use the API on 127.0.0.1 — including sessions in
     bypassPermissions mode (run any command), writing ~/.claude settings (hooks = persistence), starting CLI processes
     (`/api/warm`) creating folders (`POST /api/folders`), running any shell command in a session's folder without bypass mode and without a permission prompt (`POST /api/sessions/:id/shell`, since D10), overwriting existing files inside a session's folders except under `.git` and the GUI's own data / config (`PUT /api/sessions/:id/file`, since D11), rolling a session's files back to an earlier checkpoint (deleting files Claude created) and cutting its conversation (`POST /api/sessions/:id/rewind`, since D15; the CLI does the writes), and (since D5) creating worktrees and branches in any local repository (`POST /api/sessions` with `worktree: true`) and removing a clean stored session worktree (`DELETE /api/sessions/:id?worktree=remove`, or by archiving the session) and checking a removed one out again (`POST /api/sessions/:id/unarchive`), and (since D16) changing a session's system prompt, thinking switch and safe mode (`PATCH /api/sessions/:id`).
  3. A base URL with `user:password@` (not fixed, found 2026-10-27): `/api/models` fails ("Request cannot be constructed from a URL that
     includes credentials") and its error text echoes the full URL with the credentials to the browser. The health dot already strips them.
     Fix: build the request from a cleaned URL (as lib/model-health.js does) and strip credentials from the error text in lib/model-list.js.
  Fix when needed: random token generated at startup and required on every /api call (cookie or header), reject
  `Sec-Fetch-Site: cross-site`, and make the process-starting endpoints POST.

## Entry Points
- `server.js` — starts the HTTP server (loopback only)
- `public/js/app.js` — frontend entry (ES modules, no build step)
- Run: `node server.js`, open http://127.0.0.1:3737. Set `claudePath` (and `model`/`env` if needed) in `config.json`.
- After pulling an update: restart `node server.js`. Files in `public/` are read from disk on every load, but API
  routes load only at startup, so a new screen against an old server fails (the 404 says so).
- Develop without an API key: `CLAUDE_GUI_CONFIG=dev/config.fake.json CLAUDE_GUI_DATA=<temp dir> node server.js` (port 3738).
  `dev/fake-claude.cmd` runs on Windows only; elsewhere point `claudePath` at a shell script that runs
  `node dev/fake-claude.js "$@"`. Add `"FAKE_CLAUDE_STARTUP_MS": "2500"` under `env` to feel the real startup delay.
  For the model list, point `ANTHROPIC_BASE_URL` at any small server answering `GET /v1/models` with `{ data: [{ id }] }`.

## Key Patterns Used
- All knowledge of the CLI event format is in `lib/event-translator.js`; control-protocol calls in `lib/cli-process.js`
- Every UI update flows through one path: server broadcast -> SSE -> `public/js/events.js` -> views
- Slash commands: `public/js/commands-data.js` (built-ins of 2.1.308 + Hebrew text + where each runs) merged with the
  live catalog from the CLI in `public/js/command-catalog.js`; executed by `public/js/command-runner.js`
- Optional CLI flags are passed only when `claude --help` lists them (`lib/cli-capabilities.js`)
- The browser can only reach Claude's own files through kinds (`lib/claude-files.js`) and whitelisted CLI subcommands
  and options (`lib/cli-commands.js`); writes need an explicit folder (no fallback to the home folder)
- The UI never waits for the CLI to open a menu: read cached data (`peekCatalog`, `peekModels`) and update when the
  real answer arrives; background reads pass `ifRunning` so they never start a process
- Claude's state is a `data-state` on the working line (`working-line.js`) and on the crab inside it (`setCrabState` in `crab.js`); `data-b` (1..3) picks one of the state's behaviors; motion lives only in `public/css/animations.css`
- Significant actions are never blocked, only confirmed: panels get `guardedApi` from `public/js/risk.js` (settings with
  hooks/env/allow rules, user-wide files, MCP add, plugin install/marketplaces); also bypass/auto mode and slash commands
  that act on the Anthropic account or the cloud (design-*, schedule, ultrareview, usage-credits)

## Gotchas / Watch Out
- Session options (D16): a new per-session CLI option is an entry in `lib/session-options.js` (validation in `textChanges`, flags in `optionArgs`) plus a field in `session-store.js` `create`, `SETTING_KEYS` in `session-service.js`, and a restart key in `session-runtime.js` `applySettings` if it needs a new process. Free text never goes through argv (`quoteForCmd` refuses `%`, mangles quotes): use a file, like `session-prompt.js`. Every place that sets a permission mode must pass the session's `safeMode` to `requireMode(mode, safe)` (today `updateSession` and `answerPermission`; the check in `answerPermission` runs BEFORE the CLI is told); a CLI-reported mode change (`onModeChange`) is not blocked. `COLOR_KEYS` (server) and `public/js/session-color/palette.js` must be changed together. A new `startProcess` caller for a session process needs `withSessionEnv` as well as `withCheckpointing`. A new place that deletes a session must call `removePromptFile`.
- Rewind (D15): `session.resumeAt` must NOT be cleared until the replay of the next message arrives (`onUserReplay`): the cut lives only in the CLI's memory until a new message is written, so every restart in between (idle, settings) must pass the same `--resume-session-at`; clearing it too early brings the removed turns back, clearing it never cuts the new turns off. A message is a rewind point only when its `cliSession` equals `session.claudeSessionId` and `!forkPending`: this is what disables inherited fork items, items before `/clear` and imports, so anything that changes `claudeSessionId` on purpose (clear, a future "new conversation") changes what is rewindable. `afterUuid`: `null` = first message (fresh conversation), `false` = unknown (only code rewind). Validate the cut BEFORE restoring files (`requireCutPoint`); never take a path, folder or program from the rewind request; `rewind_files` stays out of `catalog-service.js`. Any new place that sends a user message to the CLI must go through `startTurn` / the correction path so the item gets `cliUuid` and `afterUuid`. Every new `startProcess` caller for a session process needs `withCheckpointing(config)` (today `session-runtime.js` and `runtime-spare.js`). The browser gets no `cliSession`: a button on an item does not prove a rewind is possible, the server answers 409 with a reason. `session-runtime.js` is 145 lines, `fake-claude.js` 149 (three requires joined on one line to keep the budget): add nothing there
- Files pane (D11): the file routes take the session from the server and only a path from the request; write rules live in `lib/files/safe-path.js` (no `.git` segment, no `DATA_DIR` / `CONFIG_PATH`, no uploads, no `:` on win32, regular files only): any new route that writes a file must use it. `overwrite` forces only when exactly `true`; the saved hash belongs to the text that was sent. A new way to show a file path that should be editable goes through `files/open-in-files.js` (a registry, so the viewer and the file menu do not import the pane); the split pane's thread has no edit entry. A save must call `invalidateSessionFetches` so the Changes pane and the rail refetch. The editor handles Ctrl+S and Esc itself (Esc must not stop Claude's turn); the page-wide table only has a documentation row. The tree hides `.git` always and a fixed set of folders unless "הצגת מוסתרים" is on; the filter uses the `@` index, whose hidden set differs a little. `files-pane.js` is 134 lines: split before adding to it. `app.js` got one long line: do not add more
- Shell commands (D10): the shell route's folder is always `session.cwd` and the shell is an enum; never take a folder, program or environment from the request. Every kill path matters (stop, session delete, archive, server exit and SIGINT/SIGTERM/SIGHUP): a new way to end a session must call `shell-runs`. `session.shellContext` is set only by the server when a `bang` run ends and must reach the CLI exactly once: any new place that writes a user message to the CLI has to call `shell-context.withPending` and `restore` on failure (today `startTurn` and the correction path), or `!` output is silently lost or sent twice. The prefix format is from memory, unverified. The `!` live card bypasses `thread.js` on purpose (size budget); `thread.js` is at its limit. `session-service.js` (152) and `app.js` (151) are over the ~150-line budget by a little: do not add to them. - Context menus (D7): a new place that shows a file path adds `data-file-path` (the FULL path; the Changes pane uses `joinPath(root, path)` because its paths are repo-relative from the top level, not from `session.cwd`) and gets the file menu for free; a new place that lists sessions adds `data-session-id` and calls `enableSessionMenus`. Menus are built on `showDropdown`, which has no keyboard navigation: `context-menu/menu.js` adds it, so use `openContextMenu`, not `showDropdown`, for a menu that can open from the keyboard.   Health = 2xx only (any other answer is red, no `/api/tags` fallback). Everything else outside the machine happens through Claude Code
  (model API calls, MCP/plugins) or through tools Claude runs (Bash can reach the model server's HTTP API — e.g.
  Ollama's unauthenticated /api/delete — when the user approves it or in bypass mode)
