# Gotchas

Code-level rules per area. Before changing an area, read its line here. Moved from AGENT_CONTEXT.md on 2026-11-24.

- The CLI is the source of truth, the GUI only displays (DECISIONS.md 2026-10-29): if the CLI already does it, follow the CLI; keep GUI data only for what the CLI has no place for; a departure (a second copy of history, an invented flag or control request) is said out loud in the reply and in DECISIONS.md. Already flagged GUI-only: model gate, stall clock, loop detector, "סכם ונקה", the context-window lookup, chat folder.
- Session options (D16, F): a new per-session CLI option is an entry in `lib/session-options.js` (`textChanges`, `optionArgs`, `copiedOptions`) plus a field in `session-store.js` `create`, `SETTING_KEYS` in `session-service.js` and a restart key in `session-runtime.js` `applySettings`. Free text never goes through argv (`quoteForCmd` refuses `%`): use a file (`session-prompt.js`); tool names are plain names. Every place that sets a permission mode passes the session's `safeMode` to `requireMode` (`updateSession`, `answerPermission`, checked BEFORE the CLI is told); a CLI-reported mode change is not blocked. `COLOR_KEYS` (server) and `public/js/session-color/palette.js` change together. A new `startProcess` caller needs `withSessionEnv` and `withCheckpointing`. A new place that ends or deletes a session must call `removePromptFile`, release the model gate, kill a verify run and dev servers and shell runs, and forget the stall / loop state.
- `--settings`: the per-session file holds the output style AND the verify Stop hook (`verify-hook-settings.js` merges them); pass it only when `--help` lists it. The verify secret travels in the CLI's environment, not the file. The hook is always installed; the server answers allow with no stored check. The hook command is run by the CLI's shell: refuse paths with `" % $` backtick `!`, newline, `\\`. A blocked Stop continues the SAME turn: verify notices are notice items, never user items (do not split `isTurnStart`); `session.verifying` pauses the stall clock.
- Model gate / stall: the slot is held to the real turn end (a held correction turn stays held); every exit path must release it (idle status, delete, archive of a holder = stale, 30 s stale check); a waiting turn is `modelWait` on a running session, not `session.queue`. `/btw`, corrections and warm-up bypass the gate. The stall text updates the working line in place (moving that node restarts the crab animation).
- Loop detector: only top-level tools; the loop stop is not a user stop (no "הריצה הופסקה.", it notifies as an error) and leaves queued texts parked; keep BashOutput / TaskOutput / Monitor / KillShell exempt.
- Context window: the denominator and the estimate are derived data: label them ("הערכה"), never start a CLI for the ring (`ifRunning`), never ping the cloud (custom base URL only), keep `contextInfo(session)` the ONLY place that computes a percentage, reset the estimate at `/clear` and `/compact`. Do not invent an env var to make the CLI auto-compact early.
- Robustness: `session-store.js` goes through `lib/safe-file.js` (the exit write stays synchronous; a file that failed to load is never overwritten); requiring `session-store.js` registers an exit hook that writes `data/sessions.json`, so set `CLAUDE_GUI_DATA` in experiments. The SSE hub's `resync` must reload state in `api.js` `subscribe`. Settings-file writes by the GUI use the `backup` option (`<data>/backups/`).
- Wave 2 sync: items come from `GET /api/sessions/:id/items?rev=&since=`; the revision `<epoch>.<n>` bumps only for a rebuilt list, and the rebuilt-list comparison must keep ignoring an item's own `at` (`lib/sync/item-time.js`); only item / history / delta events are filtered per tab; `status: idle` carries `outcome`.
- Rewind (D15): `session.resumeAt` is NOT cleared until the replay of the next message arrives (`onUserReplay`); a message is a rewind point only when `cliSession === claudeSessionId` and `!forkPending` (so "fork then rewind in the fork" cannot work for compare). `afterUuid`: `null` = first message, `false` = unknown. Validate the cut BEFORE restoring files (`requireCutPoint`); never take a path, folder or program from the rewind request; `rewind_files` stays out of `catalog-service.js`. Any new place that sends a user message to the CLI goes through `startTurn` / the correction path and calls `shell-context.withPending` / `restore`. Retry reuses the rewind route.
- Git writes: every git call goes through `lib/git/run.js` (`SAFE_GIT`, `SAFE_DIFF`, `core.quotepath=false`; `git()` takes `input`, `env` and `{ timeoutMs }`); never call `execFile('git')` elsewhere; every write takes the one repo lock (`repo-lock.js` keys on `path.resolve(root)`, lowercased on Windows). The writes: the session worktree (`worktree*.js`; hooks and filters run on purpose), hunk revert (no patch text in the request; the hunk hash module is shared by browser and server and must stay pure), whole-file discard (`discard-*.js`: path from the pane's status list only, `safe-path` rules, deletes untracked files, no undo), commit and push (`commit*.js`, `push.js`: never an option from the request, never `--no-verify` / `--amend` / `--force`, no pull), branch merge (`merge*.js`: branch from the stored session, aborts on conflict, never pushes), worktree cleanup (never `--force`, the branch stays). The branch view (`?mode=branch`, exact match only) hides edit actions and the commit box.
- Files pane (D11): the file routes take the session from the server and only a path from the request; write rules live in `lib/files/safe-path.js` (no `.git` segment, no `DATA_DIR` / `CONFIG_PATH`, no uploads, no `:` on win32, regular files only; `.mcp.json` and `.claude/settings*.json` view-only; protected files matched by dev + ino) and `own-files.js` (hard links to the GUI's own files): every route that writes or opens a file uses them. `overwrite` forces only when exactly `true`. A new way to show an editable path goes through `files/open-in-files.js`; a save calls `invalidateSessionFetches`; auto-save (`files/auto-save.js`) pauses on a conflict. The editor handles Ctrl+S and Esc itself.
- Hardening (2026-11-17): any new browser `fetch` to `/api/` goes through `public/js/api.js` (it adds `X-Claude-Gui: 1`; without it 403) unless the route is exempt (SSE, images, uploads, preview); a new `?cwd=` GET must use `lib/known-folders.js`; the preview route's every response (errors too) keeps its CSP and the iframe never gets `allow-same-origin` for project files.
- Dev servers (2026-11-19, `lib/preview/dev-*.js`): click only; the request is `{ name, hash }` and the server re-reads and re-hashes; the env is scrubbed; programs are resolved on the GUI's own PATH skipping project folders; killed on stop / delete / archive / exit.
- Highlighting: only highlight.js's own escaped output may be inserted as HTML (`public/js/highlight/`); the vendored files are never edited by hand (hashes in DEPENDENCIES.md). The quote reader depends on the diff row structure (`td.code`, `.sign`, `data-col`).
- Shell (D10, terminal tabs): the folder is always from the server; never take a folder, program or environment from the request; every kill path matters (stop, delete, archive, exit, SIGINT / SIGTERM / SIGHUP). `session.shellContext` is set only by the server when a `bang` run ends and must reach the CLI exactly once. A terminal's cwd is guarded by `lib/terminal/shell-sentinel.js` + `terminal-folder.js`; "open in terminal" resolves folders on the server.
- Keep-awake (`lib/keep-awake/`): hooked from `setStatus`; the child must exit when the server's pid disappears; the toggle is stored in `<data>/keep-awake.json`, `config.json` `keepAwake` is only the default and the GUI never writes `config.json`.
- Scheduling (`lib/schedule/`): old kinds stay readable and convert to `rule` only on edit; an unknown stored kind loads paused with an error; a timer tick clears the pending timer first; runs go through `createSession` + `sendMessage` (the model gate applies) and never auto-answer a prompt; the engine takes an injectable local-time helper (tests need no `TZ`).
- Chat without a project (`lib/chat-folder.js`): the server picks the folder, the API takes only a strict boolean `chat`; `chat` + `worktree` is 400; PATCH cannot change `chat` or `cwd`.
- Sidebar: groups and unread are server state (`lib/sidebar-groups/`, `markedUnread`, `lastOutcome`, `completed` cleared by `completionReset` when a session goes running); the view lives in localStorage `claude-gui.sidebar-view`; a non-boolean `pinned` is 400. `#session=<id>` opens a session and is cleared.
- Context menus (D7): a new place that shows a file path adds `data-file-path` (the FULL path); a new place that lists sessions adds `data-session-id` and calls `enableSessionMenus`. Use `openContextMenu` for a menu that can open from the keyboard. The browser's own menu stays on a text selection (so "add selection to chat" is a floating button only).
- Archived sessions (D6): `archived` / `archivedAt` are set only by `lib/session-archive.js`. Archive marks the session FIRST and stops the turn AFTER; do not swap that and do not call `stopSession` from archive. Every NEW list or counter decides about `!session.archived`. A session whose worktree was removed has no folder: any route that starts a CLI or runs in `session.cwd` goes through `requireRunnable` (409); git views answer `folderMissing`. Restore puts the folder back at the SAME path; `archiveSession` skips removal while a non-archived session uses the path (`worktreeInUse`), `deleteSession` counts every other session.
- Worktree sessions (D5): `session.cwd` is the worktree but the user's PROJECT is `worktree.source`: anything that shows or groups by folder uses `projectFolder(session)`; anything that runs git, reads files or starts the CLI uses `session.cwd`. `worktree` is set only by the server. Removal takes only the stored path and `removeWorktree` re-checks it; the branch is made with `-b`, never `-B`, and only `undoAdd` deletes one.
- Ctrl+F (`public/js/transcript/find-*.js`, `hit-stepper.js`): one bar per pane and per transcript; the row has `optional: true` (its action returning false leaves the key to the browser); Esc in the bar must `preventDefault` + `stopPropagation`.
- Shortcuts (`public/js/shortcuts/`): a new page-wide key is a row in `shortcut-list.js` plus an action given to `bindShortcuts(run)` in `app.js`; a row without `action` is documentation. Match Ctrl/Cmd + exact Shift + no Alt + `event.code`, never `event.key` for a letter or punctuation; every table shortcut gets `preventDefault`. Latin key cells in an RTL list sit in `dir="ltr"` spans.
- Dropdown placement (`popover.js` `position`): check any new dropdown at 420 px and from the far-end button.
- Transcript view (`public/js/transcript/`): a group WRAPS the existing tool rows; rows are never re-rendered, so `data-tool-id`, `data-item-index`, `settleTools` and the delegated listeners keep working. Anything drawn live goes through `thread.append`, which places it above the live elements and calls `view.appended(item, node)`. The body class `focus-view` is the separate `/focus` filter. Message times (`message-time.js`) are `at` ms on user and text items only; copy still copies the source only.
- Split view: `events.js` updates every thread showing the event's session (main thread + `view.paneThread(id)`). The same session is never in both panes. The split composer is bound to its OWN session and must never send to the main one; the side pane area and the todo strip follow the main session (except the side-question tab after `/btw` from the split pane). An open split closes below 1000 px.
- Panes: a new pane registers in `public/js/panes/panes.js` with `{ id, title, icon, render(body, session) }`; panes are tabs of ONE area (hidden, not destroyed; `render` runs only while shown), so keep state outside the DOM it rebuilds; the saved open set (`claude-gui.panes-open`) and the active tab (`claude-gui.panes-active`) are kept; below the room limit the area is a drawer whose open state is never saved. `panes/` is not `panels/` (the settings modal's pages). No timers in the rail / panes. Changes pane: redraw only when the diff text changed; Esc in the comment box `preventDefault` + `stopPropagation`; comments clear only when `send` returns true; `diff-parse.js` relies on the fixed `a/` `b/` prefixes; keep the limits (100 files, 512 KB, 2 MB, `lstat`).
- File viewer: `lib/file-view.js` is the only GET that returns file contents: roots come from the session, real paths with a separator boundary, read from the resolved path, `cwd` ignored. One delegated listener (`enableFileLinks`) handles every open button.
- Background tasks: idle shutdown is skipped while `runtime.runningTasks > 0` (and while a prompt is pending); tasks are never persisted and become `killed` when the CLI exits.
- `/btw`: `side_question` costs tokens, so it has its own route and is NOT in the generic `/control` whitelist; the unsupported-CLI error keeps the text "not supported by this Claude Code version" (`isUnsupported`, `panels/kit.js`).
- Notifications: preferences in localStorage `claude-gui.notifications`; triggers in `events.js` (`status: idle` -> done / error; a user-stopped turn notifies nothing; a loop stop or a verify cap is an error; `permission` with a new requestId -> waiting). The tab title is built only in `page-status.js`.
- Stale server: `public/` changes take effect on reload, `lib/` only after restarting `node server.js`; keep the "נתיב API לא קיים" 404 text.
- Warm-up: a spare process (`spare-…`) is adopted by `createSession` only when cwd, mode, model and effort match exactly; it closes after 3 idle minutes (it does not check the new session's tool limits). Never key anything else on the runtime's sessionId before adoption.
- Models: with one model the chip is static on purpose; a base URL on anthropic.com counts as Anthropic.
- Crab: built in `public/js/crab.js` (a new behavior = a higher `BEHAVIORS` plus CSS for every state); `public/icon.svg` is a separate copy (change both). New items never move the working line.
- Attachments: messages and queue entries keep references only; bytes are read again when the turn is sent; with attachments the composer never treats the text as a GUI command; `/api/images/:id` and `/api/uploads/:id/:name` are served before the JSON routes; `sweep` removes unreferenced ones older than a day.
- Copy buttons find their text through a WeakMap in `render-items.js` (`copySourceOf`).
- Mid-turn corrections (D9): a correction is written to the CLI, never stored in `session.queue`; a held turn (`holdTurn`) keeps `turnActive` true on purpose (Stop, the idle timer, `handleExit`, the stall clock and keep-awake rely on it) and `onTurnEnd` fires once at the real end; only a SUCCESSFUL result is held; anything that finds "the turn start" in the items uses `isTurnStart`.
- Queue: `sendMessage` on a running session appends to `session.queue` unless `delivery === 'correct'` and the runtime can take it; `onTurnEnd` sends the next; Stop empties the queue BEFORE interrupting and returns the texts; after a crash or restart the queue waits for "שליחת הבאה".
- Conversation = the CLI's file: never store items in `sessions.json` or edit `session.items`; add a GUI-only item with `pushExtra` (`session-common.js`; extras get no `at`); change the conversation through the CLI. The fake CLI writes its transcript under `CLAUDE_CONFIG_DIR`: set it for experiments (tests use a temporary one). `CLAUDE_CODE_ENTRYPOINT=claude-code-gui` (`lib/session-env.js`) is what makes the CLI's `/resume` picker list a GUI conversation: do not drop it.
- Environment variables (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`) are inherited from the shell that starts the server or set under `env` in `config.json`. Each open session keeps a CLI process (100–300 MB) until `idleMinutes`. Settings without a live control request (effort, agent, output style, add-dir, tool limits) restart the process with `--resume` on the next message.
- 2.1.246 lacks the control requests `list_permission_rules`, `get_hooks_listing`, `get_memory_dialog`, `get_skills_dialog`, `get_status`; panels degrade (`isUnsupported`); the server answers HTTP 501; skills and the auto memory are read from disk. `--permission-prompt-tool stdio` is required for permission prompts (hidden from `--help`); 2.1.x names the "default" mode "manual". On the user's machine `claude` on PATH is an interactive wrapper that asks for a model: `claudePath` must point to the real CLI. `.cmd` shims run through cmd.exe with `lib/spawn-utils.js` quoting; JSON goes through files, never arguments; an argument with `%` is refused.
- The GUI server's outbound calls: `GET {ANTHROPIC_BASE_URL}/v1/models` (model list; health dot) and the context-window lookup (`POST /api/show`, `GET /api/ps`); only for a custom base URL, never the cloud; `git push` goes to the repository's own remote on the user's click. Everything else outside the machine goes through Claude Code or tools Claude runs.
